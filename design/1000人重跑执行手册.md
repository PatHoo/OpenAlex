# 1,000 人重跑执行手册（`--stage all`）

用途：当 `pipeline/data/batch_001/works.jsonl` 等中间产物缺失、需要从 OpenAlex 重新抓取
并用同一口径重建数据库、分析与交付物时，按本手册执行。

脚本：`pipeline/rerun_1000.py`。一条命令完成：
WP0 生成子集 → WP1/WP2 抓取（双 key 轮换）→ WP3–WP16 落库分析 → 重导出 Excel 与平台快照。

---

## 0. 执行前必须确认（不然会污染数据）

- [ ] 数据库里是**已恢复的 1,000 人基线**或**只建了 schema 的空库**。若当前是三人小样 POC
      （`scholar=3`、`work` 极少），**不要执行**，先按部署清单第 4 节恢复基线。
- [ ] 现在就备份交付物（脚本会备份数据库和 batch 目录，但**不备份已发布文件**）：
      ```bash
      cd /srv/openalex
      tar czf /var/backups/openalex_web_$(date +%F).tar.gz web/data output/client_workbook
      ```
- [ ] 磁盘：抓取阶段需要约 **8.6 GB** 给 `works.jsonl`，另留 20 GB 给数据库与备份。
- [ ] 网络：能访问 `api.openalex.org`；两把 key 均已通过邮箱激活。
- [ ] 先在**本机 Python** 跑一次离线测试（不联网、不连库）：
      ```bash
      cd /srv/openalex/pipeline
      python3 -m unittest discover -s tests -v     # 应 71 项全通过
      ```

## 1. 云主机（原生 Linux）完整命令

### 1.1 一次性准备凭据文件（不要写进仓库、不要留在 shell 历史里）

```bash
sudo install -d -m 700 /etc/openalex
sudo tee /etc/openalex/api.env >/dev/null <<'EOF'
OPENALEX_API_KEY_1='第一把key'
OPENALEX_API_KEY_2='第二把key'
OA_COST_CAP_USD='2.20'
OA_RATE='30'
EOF
sudo chmod 600 /etc/openalex/api.env
sudo mkdir -p /var/log/openalex
```

`/etc/openalex/db.env` 由部署清单第 4.4 节建立，内容应包含：

```bash
OA_PATH_MODE='linux'
PGHOST='127.0.0.1'
PGPORT='5432'
PGUSER='postgres'
PGDATABASE='openalex'
PGPASSWORD='数据库密码'
```

> 原生 Linux 下 `dbutil` 与 `pg_dump` **不会**自动从 `~/.openalex_db_pass` 读密码，
> `PGPASSWORD` 必须由 `db.env` 提供，否则 WP3 和写库步骤会失败。

### 1.2 完整执行命令

**推荐直接用一键脚本**：`design/run_rerun_1000.sh` 已封装下面的命令，含预检、交付物备份、
日志和退出码提示，拷到云主机即可执行：

```bash
chmod +x run_rerun_1000.sh
./run_rerun_1000.sh                # 默认 --stage all
```

需要改参数时：`./run_rerun_1000.sh --stage fetch --fresh`、`--dry-run`、`--no-tests`。
路径不同可覆盖 `OPENALEX_ROOT` / `PY` / `ENV_DIR` / `LOG_DIR` / `BACKUP_DIR`；
本地 WSL 用 `SKIP_ENV_FILES=1` 走当前 shell 已导出的环境变量。

下面是不用脚本时的等价原始命令，便于核对每一步：

```bash
set -a
source /etc/openalex/db.env
source /etc/openalex/api.env
set +a
set -o pipefail

cd /srv/openalex/pipeline

python3 -u rerun_1000.py --stage all \
  2>&1 | tee /var/log/openalex/rerun_1000_$(date +%Y%m%d_%H%M%S).log

echo "EXIT=$?"
```

`EXIT` 表示结果：

| 退出码 | 含义 | 处理 |
|---:|---|---|
| 0 | 全部完成 | 做第 3 节验收 |
| 2 | 配置错误（如没读到 key） | 检查 `/etc/openalex/api.env` |
| 3 | 暂停：额度耗尽 / 成本超限 / 请求失败 | 见 2.2，修好后重跑同一条命令 |
| 其他 | 某个 DB 步骤失败 | 看日志里 `[FATAL]` 行，见 2.3 |

## 2. 本地 WSL 完整命令

路径为归档工作区示例，按实际调整；WSL 会自动识别模式，无需 `OA_PATH_MODE`。

```bash

```

## 3. 执行期间

### 3.1 看进度

日志里每 25 人输出一行 `[PROGRESS]`，含完成数、累计成本、用时和每人耗时。
不要去数 `works.jsonl` 的行数（8.6 GB，极慢）；进度只看日志和 `checkpoint.json`：

```bash
python3 - <<'PY'
import json
cp = json.load(open('data/batch_001/checkpoint.json', encoding='utf-8'))
print(f"wp1={sum(v.get('wp1') for v in cp.values())} "
      f"wp2={sum(v.get('wp2') for v in cp.values())} "
      f"total={sum(v.get('works_count', 0) for v in cp.values())}")
PY
cat data/batch_001/cost_ledger.json     # 已花美元与请求数
```

### 3.2 暂停后如何续跑

所有暂停都是**干净暂停**：当前学者未标完成、未写半截作品、成本账本已落盘。
重新 `source` 两个 env 文件，再执行**完全相同的命令**即可：

```bash
set -a; source /etc/openalex/db.env; source /etc/openalex/api.env; set +a
cd /srv/openalex/pipeline
python3 -u rerun_1000.py --stage all 2>&1 | tee -a /var/log/openalex/rerun_1000_*.log
```

- 退出码 3 且原因是 `AllKeysExhausted`：换新的 key 到 `api.env`，或次日额度重置后再跑。
- 原因是 `CostCapExceeded`：确认余额后调高 `OA_COST_CAP_USD`（如 3.00）再跑。
- 抓取已完成但 DB 步骤失败：不必重抓，改用 `python3 -u rerun_1000.py --stage db`。

### 3.3 从零重跑

在完整命令中给抓取加 `--fresh`：旧 `batch_001` 会先改名成 `batch_001_bak_<时间戳>`，
再从 WP0 重新生成子集。**不要用 `--fresh` 做普通续跑**。

```bash
python3 -u rerun_1000.py --stage fetch --fresh
```

## 4. 执行后验收

```bash
cd /srv/openalex/pipeline
source /etc/openalex/db.env

# 4.1 抓取完整性（应接近 1,000 / 1,000，作品约 922,627 行）
python3 - <<'PY'

print('wp1:', sum(v.get('wp1') for v in cp.values()),
      'wp2:', sum(v.get('wp2') for v in cp.values()),
      'works:', sum(v.get('works_count', 0) for v in cp.values()))
PY

# 4.2 数据库行数（基线口径）
PGPASSWORD="$PGPASSWORD" psql -h 127.0.0.1 -U postgres -d openalex -c \
  "SELECT (SELECT count(*) FROM scholar) AS scholar,
          (SELECT count(*) FROM work) AS work,
          (SELECT count(*) FROM authorship) AS authorship,
          (SELECT count(*) FROM mobility_event) AS events;"

# 4.3 交付物时间戳与快照口径
ls -lh /srv/openalex/web/data/snapshot.json /srv/openalex/output/client_workbook/*.xlsx
python3 -c "import json;print(json.load(open('/srv/openalex/web/data/snapshot.json',encoding='utf-8'))['generated_at'])"
```

核对要点：

- `work` 约 865,111、`authorship` 约 846,012、`scholar` 约 896。
- `snapshot.json` 的 `generated_at` 是本次时间；页面仍标注为 **1,000 人试跑快照**，不得冒充全量。
- DID 部分 treated 仍只有 5 人，只证明流程可跑，不能当政策结论。

## 5. 回滚

| 对象 | 位置 | 恢复方式 |
|---|---|---|
| 数据库 | `pipeline/data/backups/openalex_<时间戳>.dump`（脚本写库前自动生成） | `pg_restore --clean --if-exists -h 127.0.0.1 -U postgres -d openalex <dump>` |
| 中间产物 | `pipeline/data/batch_001_bak_<时间戳>/`（仅 `--fresh` 时生成） | 改名回 `batch_001` |
| 已发布文件 | 第 0 节的 `/var/backups/openalex_web_<日期>.tar.gz` | 解压覆盖 `web/data` 与 `output/client_workbook` |

若 DB 步骤中途失败，脚本会停止后续步骤并打印备份路径；不要手动跳过失败步骤继续，
应先按日志修复，再重跑 `--stage db`。

## 6. 口径说明

- 成本上限默认 **$2.20**，按官方计费 `search $0.001/次`、`list+filter $0.0001/次`
  在请求发出前拦截；1,000 人实测约 $1.98，含双 key 重试缓冲。
- `OA_RATE=30` 为免费 key / prepaid 的官方上限；实测若遇到 429 可下调到 `8`。
  但新账号首 $1 按 $0.10/5 分钟释放，提高速率不等于能立刻跑完。
- 重跑**不是原快照的逐字节恢复**：OpenAlex 消歧与检索排序会变，`author_id`、
  候选与请求 sha256 都可能不同。对外必须标注新的抓取日期，不能声称与旧版完全一致。
