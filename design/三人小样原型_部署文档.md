# 三人小样本地 PostgreSQL 原型 · 部署文档

版本：v1.1 · 2026-11-21（修复硬编码口令、危险重置建议与核对流程）
目标：在本机起一个 PostgreSQL 16 数据库，导入 Becke / Perdew / Newman 三人的真实小样数据，跑通关系库查询与 AGE 图查询，用结果对拍原始 Excel。
配套文件：
- `schema.sql` — 建表脚本（25 张表 + 视图 + 触发器；Part 7 的 AGE 目标标签默认不执行）
- `三人小样_seed.sql` — 从 1030 版 Excel 真实抽取的种子数据（含 3 条源名单行 / 139 面板行 / 6 事件 / 9 分类）
- `三人小样_AGE投影.sql` — 小样图投影与 V1–V5 验证查询
- `api_request_seed.sql` — 从 `A基线请求清单` 自动提取的 64 条 API 请求日志（幂等）
- `api_request_crossref_seed.sql` — 从 `A补查Crossref` 提取的 156 条 Crossref 请求日志（幂等）
- `event_evidence_seed.sql` — 6 个事件 × 5 项判据 = 30 条事件证据（幂等）
- `rule_test_seed.sql` — 19 项规则测试（全部 passed，幂等）
- `verify_poc.sql` — 导入后一致性/完整性核对与阈值演示
- `关系库+AGE_图模式设计.md` — 设计说明

## 1. 方案选择

| 方案 | 适合场景 | 难度 | 说明 |
|---|---|---|---|
| **A. Docker Desktop（推荐）** | 想最快跑起来、以后要换版本 | ★☆☆ | 一条命令起 PG+PostGIS+AGE，环境隔离，不污染系统 |
| **B. Windows 原生安装** | 不能装 Docker、要长期用 | ★★★ | PostgreSQL 官方 MSI + PostGIS + AGE 需自行编译，AGE 部分最麻烦 |
| **C. 降级：只装 PostgreSQL** | 只想验证关系库部分 | ★☆☆ | 跳过 AGE，图查询用 SQL 递归 CTE 模拟，无需编译扩展 |

**强烈建议先走方案 A 或 C**。AGE 在 Windows 原生编译坑较多，而三人小样的核心验证（面板、C1–C5、A/B 双轨）在关系库里就能完成 90%。

## 2. 方案 A：Docker Desktop 部署（推荐）

### 2.1 安装 Docker Desktop

```powershell
winget install Docker.DockerDesktop
```

安装后重启，打开 Docker Desktop 确认右下角鲸鱼图标变绿。

### 2.2 拉取并启动镜像

Apache AGE 官方提供带扩展的镜像。选 PG 16 对应版本：

```powershell
$env:OPENALEX_DB_PASSWORD = '<请设置强密码，例如 20 位以上随机串>'
$env:PGPASSWORD = $env:OPENALEX_DB_PASSWORD   # 供后续 psql 命令使用
docker pull apache/age:release_PG16_1.6.0
docker run -d --name openalex-pg ^
  -e POSTGRES_PASSWORD=$env:OPENALEX_DB_PASSWORD ^
  -e POSTGRES_DB=openalex ^
  -p 5432:5432 ^
  apache/age:release_PG16_1.6.0
```

> 若该镜像拉取失败（网络原因），退回通用镜像并手动装扩展：
> ```bash
> docker pull postgis/postgis:16-3.4
> docker run -d --name openalex-pg -e POSTGRES_PASSWORD=$env:OPENALEX_DB_PASSWORD ^
>   -e POSTGRES_DB=openalex -p 5432:5432 postgis/postgis:16-3.4
> ```
> 此镜像自带 PostGIS，AGE 需另装（见 2.4）。

### 2.3 验证连接

```powershell
docker exec -e PGPASSWORD=$env:OPENALEX_DB_PASSWORD openalex-pg psql -U postgres -d openalex -c "SELECT version();"
```

### 2.4 （可选）在通用镜像里装 AGE

```bash
docker exec -it openalex-pg bash
apt-get update && apt-get install -y postgresql-16-age   # 若 apt 源有
# 或按 AGE 官方源码编译：git clone https://github.com/apache/age.git && make install
```

验证：

```sql
CREATE EXTENSION IF NOT EXISTS age;
LOAD 'age';
SELECT create_graph('mobility');
```

## 3. 方案 C：只装 PostgreSQL（最快验证关系库）

### 3.1 安装

```powershell
winget install PostgreSQL.PostgreSQL.16
```

安装时自己设置一个强密码，并在终端里放入环境变量（PowerShell：`$env:PGPASSWORD = '<你的强密码>'`；bash：`export PGPASSWORD='<你的强密码>'`）。下文所有 `psql` 命令都通过该变量读取密码，不把口令写进命令或文档。勾选安装 pgAdmin 和命令行工具。

### 3.2 创建数据库

把 PostgreSQL 的 `bin` 目录加入 PATH（默认 `C:\Program Files\PostgreSQL\16\bin`），然后：

```bash
psql -U postgres -c "CREATE DATABASE openalex;"
```

### 3.3 PostGIS（可选，本小样不用空间函数也能跑）

```bash
psql -U postgres -d openalex -c "CREATE EXTENSION IF NOT EXISTS postgis;"
```

> 若提示找不到扩展，跳过即可。种子脚本里的 `lat/lon` 是普通数值列，不依赖 PostGIS。

## 4. 导入数据（方案 A / C 通用）

### 4.1 执行建表脚本

在 `design/` 目录下：

```bash
psql -U postgres -d openalex -f schema.sql
```

预期输出：一串 `CREATE TABLE` / `CREATE INDEX` 成功信息，无 ERROR。
若报 `type "geography" does not exist` → 说明没装 PostGIS，把 `schema.sql` 里 `geom GEOGRAPHY(POINT, 4326)` 那一行删掉或注释即可。

### 4.2 导入种子数据

```bash
psql -U postgres -d openalex -f 三人小样_seed.sql
```

预期：看到 `BEGIN`、`INSERT 0 1` 若干次、`COMMIT`。

### 4.2b 导入 API 请求日志（可选但推荐）

```bash
psql -U postgres -d openalex -f api_request_seed.sql
```

预期：`INSERT 0 64`、`setval 64`、`COMMIT`。脚本按 `request_id` 1..64 幂等更新，重复执行不会产生重复行。原始清单缺少逐条 `backend_path` / `error_code`，最后 4 条请求缺少 `bytes`，这些字段保留 NULL。

继续导入 Crossref 补查请求（URL 按 DOI 推导）：

```bash
psql -U postgres -d openalex -f api_request_crossref_seed.sql
```

预期：`INSERT 0 156`、`setval 220`、`COMMIT`。`request_id` 65..220，`backend_path` 取原表 `raw_path`，原表无时间戳 / sha256 / 字节数，保留 NULL。

继续导入事件证据与规则测试：

```bash
psql -U postgres -d openalex -f event_evidence_seed.sql
psql -U postgres -d openalex -f rule_test_seed.sql
```

预期：事件证据 `INSERT 0 30` / `setval 30`，规则测试 `INSERT 0 19`。原表缺失的逐事件份额值保留 NULL，B50/B70 敏感性写在 `note`。

### 4.3 验证导入完整性


## 5. 跑通关系库查询（核心验收）

以下每条查询都对应原方案的一个口径，建议逐条执行并核对预期结果。

### 5.1 三人身份与分类现状

```sql
SELECT s.scholar_id, s.display_name,
       string_agg(DISTINCT i.external_id, ', ') AS ids,
       c.rule_version, c.D, c.I, c.S,
       coalesce(c.observed_class,'—') AS observed,
       CASE WHEN c.formal_class IS NULL THEN '留空(不确定)'
            ELSE c.formal_class END AS formal,
       c.is_classified
FROM scholar s
JOIN identity_map i USING (scholar_id)
JOIN mobility_class c USING (scholar_id)
WHERE c.rule_version = 'A_base_060'
GROUP BY s.scholar_id, s.display_name, c.rule_version, c.D, c.I, c.S,
         c.observed_class, c.formal_class, c.is_classified
ORDER BY s.scholar_id;
```

**预期**：Becke、Perdew 的 `formal` 为"留空(不确定)"、observed=M6；Newman 的 formal=M8、is_classified=true。这正是原报告的核心结论。

### 5.2 六条有效迁移事件 + 证据分级

```sql
SELECT e.event_id, s.display_name, e.event_type,
       e.paper_year AS 署名年,
       coalesce(e.actual_year::text,'NULL') AS 实际年,
       e.gap_years AS 差值,
       e.evidence_level, e.year_source
FROM mobility_event e JOIN scholar s USING (scholar_id)
WHERE e.rule_version='A_base_060'
ORDER BY e.event_id;
```

**预期**：6 行；Becke 的 2 条 `actual_year=NULL`、`year_source=signature_proxy`、`level=Possible`；其余 4 条 `external_actual`、`Confirmed`、差值均为 1。

### 5.3 A/B 双轨不覆盖验证

```sql
SELECT s.display_name, c.rule_version,
       c.D, c.I, c.S,
       coalesce(c.formal_class,'—') AS formal
FROM mobility_class c JOIN scholar s USING (scholar_id)
ORDER BY s.scholar_id, c.rule_version;
```

**预期**：9 行（3 人 × 3 版本）。Becke 在 `B_sens_070` 下 `S` 相关指标变化（原 Excel 显示 possible_migrations 由 1 升为 2），但 A 轨数据不受影响。

再验证 A 轨不可变触发器：

```sql
UPDATE mobility_class SET formal_class='M8' WHERE scholar_id=1 AND rule_version='A_base_060';
```

**预期**：报错 `baseline rule_version A_base_060 is immutable`。这是设计意图，不是 bug。

### 5.4 面板完整性：LOCF 禁用检查

```sql
-- 事件年份对应的面板必须是实观测年
SELECT e.event_id, e.paper_year, ap.observation_status
FROM mobility_event e
JOIN annual_panel ap ON ap.scholar_id=e.scholar_id AND ap.year=e.paper_year
WHERE ap.is_imputed = true;
```

**预期**：0 行。若有行，说明违规。

### 5.5 Newman 年度轨迹（关系库版，对拍 Excel）

```sql
SELECT ap.year, ap.primary_country AS 国家,
       i.canonical_name AS 机构, i.city, i.lat, i.lon,
       ap.note AS 最终事件
FROM annual_panel ap
LEFT JOIN institution i ON i.institution_id=ap.primary_institution_id
WHERE ap.scholar_id=3 AND ap.primary_institution_id IS NOT NULL
ORDER BY ap.year;
```

**预期**：1991 Oxford(GB) → 1992 Cornell(US) → 1997 Santa Fe → 2003 Michigan，坐标与 Excel 一致；`最终事件` 列出现 `C2(1992) / C1(1997) / C3(1998) / C1(2003) / C3(2016)`。

### 5.6 C1–C5 候选识别视图

```sql
SELECT * FROM v_event_candidate
WHERE scholar_id=3 AND event_type IS NOT NULL
ORDER BY paper_year;
```

**预期**：能识别到国家/机构变化年份；由于种子只有年度主状态、没有逐篇署名占比，视图是"演示口径"，真实事件以 `mobility_event` 表为准。

### 6.2 投影三人节点与边

```sql
-- 学者节点
SELECT * FROM cypher('mobility', $$
  UNWIND [{sid:1,name:'Becke'},{sid:2,name:'Perdew'},{sid:3,name:'Newman'}] AS r
  CREATE (s:Scholar {sid:r.sid, name:r.name}) RETURN s
$$) AS (v agtype);

-- 机构节点（从关系库生成，示意写 2 个）
SELECT * FROM cypher('mobility', $$
  CREATE (i:Institution {iid:9, name:'University of Oxford', city:'Oxford', lat:51.75222, lon:-1.25596})
  CREATE (j:Institution {iid:11, name:'University of Michigan', city:'Ann Arbor', lat:42.27756, lon:-83.74088})
  RETURN i,j
$$) AS (a agtype, b agtype);

-- 事件节点 + 经历边（Newman C2）
SELECT * FROM cypher('mobility', $$
  MATCH (s:Scholar {sid:3})
  CREATE (e:Event {eid:4, type:'C2', paper_year:1992, actual_year:1991, level:'Confirmed'})
  CREATE (s)-[:EXPERIENCED]->(e)
  RETURN e
$$) AS (v agtype);
```

### 6.3 图查询验证

```sql
-- Newman 的经历事件
SELECT * FROM cypher('mobility', $$
  MATCH (s:Scholar {sid:3})-[:EXPERIENCED]->(e:Event)

$$) AS (name agtype, type agtype, yr agtype, lvl agtype);
```

**预期**：返回 `Newman, C2, 1991, Confirmed`。

## 7. 常见故障排查

| 症状 | 原因 | 解决 |
|---|---|---|
| `psql: command not found` | PATH 未包含 bin 目录 | 加入 `C:\Program Files\PostgreSQL\16\bin` |
| `password authentication failed` | 密码不对 | 用安装时设的密码；或 `psql -U postgres` 免密（本机 trust） |
| `type "geography" does not exist` | 无 PostGIS | 装 PostGIS，或删 schema.sql 里的 geom 列 |
| `relation "xxx" already exists` | 重复执行 | 推荐新建空库重新导入。若必须原地清理，**先备份**（`pg_dump -U postgres -d openalex -f backup.sql`），确认备份可用后再执行 `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`——该操作会不可恢复地删除库中全部数据 |
| 触发器报错挡住 UPDATE | A 轨不可变保护 | 这是设计意图；要改就改 B 轨 |
| AGE `LOAD 'age'` 失败 | 扩展未装 | 走方案 C，跳过图部分 |
| 中文乱码 | 客户端编码 | psql 里执行 `\encoding UTF8`；PowerShell 设 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` |
