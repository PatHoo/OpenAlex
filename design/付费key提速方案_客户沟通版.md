# 付费 key 提速方案（客户沟通版）

> 用途：客户提出"5000 人扩容要更快"时，说明怎么付费、能快多少、要做什么。
> 官方规则核实日期：**2026-11-25**（OpenAlex 帮助中心 Pricing / Authentication / Buying & renewing 页面）。
> 结论先行：**不需要换 key 类型，给现有 key 充值预付额度即可。买 $10 预付，5,000 人从约 5 天缩短到约 1.5–3 小时。**

---

## 一、先纠正一个常见误解

OpenAlex 的"付费"不是把免费 key 换成另一种 key，而是**在免费额度之上叠加预付额度**：

- 每个账号每天仍有 **$1 免费额度**（UTC 午夜重置）；
- 免费额度用完后，自动扣该账号的**预付余额**；
- 预付余额按 **$1  increments** 自助购买，没有最低消费门槛；
- 预付余额 **3 个月内有效**，每次新购买会把全部余额的有效期重新刷新；
- 结账时可申请**公司抬头发票 / VAT 发票**（填账单地址与税号）。

所以现有两把 key 不用换，只要给其中一把充值即可。

---

## 二、官方计费与限速规则（核实值）

| 档位 | 每日 API 额度 | 每秒请求上限 | 价格 | 备注 |
|---|---|---|---|---|
| 免 key | 很少 | 10 req/s | 免费 | 不支持游标翻页，本项目不适用 |
| **免费 key** | $1/天 | **30 req/s** | 免费 | 新账号首 $1 按 $0.10/5 分钟释放 |
| **预付额度** | 叠加在免费 $1 之上 | **30 req/s** | 按量，$1 起充 | **不受新账号节流限制**；3 个月有效 |
| Member（年付） | $20/天 | 50 req/s | $5,000/年（约 ¥36,000） | 含管理后台；$7,300/年用量 |
| Member+（年付） | $100/天 | 50 req/s | $10,000/年（约 ¥72,000） | 含每日快照同步、基础支持 |
| Partner（年付） | $200+/天 | 50 req/s | $20,000+/年（约 ¥144,000 起） | 含全量支持、3 个高能用户 key |

**关键细节：新账号首 $1 的节流（$0.10/5 分钟，约 50 分钟花完）不适用于预付额度**。这正是上一轮 1,000 人跑了 5 小时 13 分的原因——免费 key 处于首 $1 节流期，而不是 30 req/s 限速卡住。买预付后这部分节流被绕过。

## 三、三档提速方案对比

| | 做法 | 5,000 人耗时 | 本次成本 | 适用 |
|---|---|---|---|---|
| **A 不提速** | 维持现状两把免费 key | 约 **5 天**（跨每日额度） | $9.8（全部由免费额度覆盖） | 不急、预算为零 |
| **B 预付额度（推荐）** | 主 key 充 **$10** 预付 | 约 **1.5–3 小时** | **$10（约 ¥72）** | 一次性扩容到 5,000 人 |
| **C 年付 Member** | $5,000/年，每日 $20 | 约 1 小时 | ¥36,000/年 | 长期高频跑批 + 需要每日快照同步 |

**推荐 B**。C 档对"一次性扩到 5,000 人"严重过剩——一年费用够买约 500 次同样的扩容；除非客户本来就需要 Member 附带的每日数据同步和管理后台，否则不建议。

### B 档费用构成

- 5,000 人预估总消耗 **$9.8**；
- 当天免费额度抵扣 $1，预付扣约 **$8.8**；
- 建议买 **$10**（约 ¥72），留 $1.2 余量应对重试与价格波动；
- 剩余预付余额 3 个月内有效，可用于后续补跑或验收复现。

## 四、推荐方案 B 的落地步骤

### 客户侧（需要客户账号与付款）

1. 用**持有主 key 的那个 OpenAlex 账号**登录 <https://openalex.org/pricing>。
2. 选择预付额度（pay as you go），按 $1  increments 购买 **$10**，刷卡支付。
3. 结账时勾选公司/VAT 发票，填账单地址与税号（如需报销）。
4. 确认 key 类型：在 **Settings → API key** 里复制的**账户主 key**。
   ⚠️ 不要用 AI agent 生成的 key——官方明确这类 key **只花免费额度，永远不会扣预付余额**，买了预付也用不上。
5. 把充值后的 key 交给我们更新到服务器（或客户自行更新，我们给命令）。

### 我们侧（技术改动很小）

1. 将充值后的 key 写入 `/etc/openalex/api.env` 的 `OPENALEX_API_KEY_1`；第二把 key 保留作备份，不必充值。
2. 成本闸门 `OA_COST_CAP_USD=11` **保持不变**——它是总额度上限，与额度来源无关，仍会在请求发出前拦截。
3. 现有额度查询脚本已修好预付余额显示（官方字段 `prepaid_balance_usd`），跑批时可实时看预付余额。
4. 执行 `./run_rerun_5000.sh`（全量重抓 5,000 人，原 1,000 人数据先备份）。
5. 完成后校验并原子切换快照，客户看到 5,000 人数据。

### 预计时间构成

| 阶段 | 预估 |
|---|---|
| 免费 $1 按新账号节奏释放 | 约 50 分钟（若账号已过新手期则无此等待） |
| 预付 $8.8 按 30 req/s 跑批 | 约 25–40 分钟 |
| 数据库导入（约 427 万 works 行）+ 分析 + 导出 | 约 1–2 小时 |
| **合计** | **约 1.5–3 小时** |

## 五、风险与注意事项

| 事项 | 说明 |
|---|---|
| agent key 不能用预付 | 必须用账户主 key；这是最容易踩的坑，买之前先确认 |
| 预付 3 个月过期 | 每次新购买会刷新全部余额；建议扩容前再买，别提前太久 |
| 免费额度仍按日重置 | 当天 $1 免费额度和预付是叠加关系，不是替代 |
| 成本闸门仍生效 | `$11` 上限保护不会因买预付而失效；超额前自动停 |
| 不要中途换 key | 预付绑在单一账号/key 上，切到未充值的 key 会回到 $1/天节奏 |
| 额度归属 | 谁的账号充值、发票开给谁，需客户内部确认 |
| 年付自动续费 | 若选 C 档，官方年付默认自动续期，退订需邮件联系销售 |

## 六、需要客户拍板

1. 选 **B（一次性预付 $10）** 还是 C（年付 Member）？
2. 用哪个账号的 key 充值？发票抬头与税号？
3. 是否要多买一些预付余额，为后续复跑或 10 万人档试点预留？（建议不多买，3 个月有效期可能用不完）
4. 是否希望由客户自行购买、我们提供操作截图指导，还是客户提供账号由我们代操作？（涉及付款账号安全，建议客户自购）
