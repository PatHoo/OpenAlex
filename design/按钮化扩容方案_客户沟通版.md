# 云端「一键扩容到 5,000 人」按钮化方案（客户沟通版）

> 用途：与客户讨论"点击按钮把学者数从 1,000 扩到 5,000"的实现方式、边界与待确认事项。
> 结论先行：**技术上完全可做，但按钮不是"立刻变出 5,000 人"，而是"启动一个约 5 天自动完成的任务"。**
> 这一点是客户预期管理的重点，建议在第一次沟通时就把时间口径讲清楚。

---

## 一、客户诉求与我们的对应理解

| 客户说法 | 对应到系统里的动作 |
|---|---|
| "云端 1,000 人先达到预期" | 静态快照 + 26-sheet 工作簿部署上云，客户浏览不查数据库 |
| "点按钮把学者数搞到 5,000" | 触发一次全量重跑：重建 5,000 人子集 → 抓取 → 落库 → 分析 → 重新导出快照与工作簿 → 切换对外数据 |
| "10 万人规模另购服务器" | 本期不做，架构预留（子集规模已参数化，成本闸门可覆盖） |

**关键理解**：按钮触发的是**后台任务**，不是页面内同步计算。原因有两个——跑批要花约 5 天，且浏览器关掉后任务必须继续跑。

---

## 二、必须提前对齐的三个硬约束

这三条不是开发选择，是服务商规则与已实测结果，建议沟通时逐条讲明。

### 1. 时间：约 5 天，不是几分钟

- 1,000 人档实测：10,362 次请求、$1.9621、抓取耗时 5 小时 13 分。
- 5,000 人档线性外推：约 51,810 次请求、**$9.8**、works 约 427 万行、入库约 10.5 GB。
- 免费 key 每把每天 $1 额度，现有两把 key 合计 **$2/天**，因此 $9.8 至少跨 **5 个自然日**。
- 脚本已具备断点续跑能力：每日额度耗尽后自动暂停，次日重置后从断点继续，**不需要人每天点一次**。
- 若客户希望缩短到 1 天以内，需要提供**付费额度或更多 key**；这是唯一有效的提速手段（单纯提高请求速率无效，首月按金额节流）。

### 2. 成本：$9.8 是确定支出，需要明确归属

- $9.8 是 OpenAlex API 费，与服务器费无关，点一次就发生一次。
- 从 1,000 扩到 5,000 是**全量重抓 5,000 人**（包含原 1,000 人），不是只补 4,000 人，因此按 $9.8 而不是 $7.8 预算。
- 原 1,000 人数据会先备份，不会被覆盖丢失。
- 建议按钮上做二次确认，明示"本次预计消耗约 $9.8 额度"。

### 3. 数据切换：跑批期间客户仍看旧版

- 5 天跑批过程中，对外展示的仍是 1,000 人快照，页面照常可用。
- 新快照生成并校验通过后，才原子切换，**不会出现半截数据**。
- 旧快照保留一份，可一键回退。

## 三、三种实现方式对比

| 方案 | 客户体验 | 开发范围 | 适用情况 |
|---|---|---|---|
| **方案 0：不按钮化** | 客户提需求，我们后台代跑，完成后通知 | 零开发，现有命令行脚本即可 | 客户只想看结果、不想管过程 |
| **方案 1：按钮 + 进度页（推荐）** | 客户点一次按钮，页面显示进度/花费/剩余天数，完成后自动看新数据 | 触发端 + 调度器 + 只读进度 API + 前端按钮 | 本次诉求的最小完整闭环 |
| **方案 2：按钮 + 任务控制台** | 在方案 1 基础上增加暂停、续跑、取消、历史任务、邮件/企微通知 | 方案 1 + 状态机 + 通知 + 审计后台 | 客户要自主运维、多人协作 |

**推荐方案 1**，理由是它已经覆盖客户"点按钮"的核心诉求，且复用现有全部跑批逻辑，不重复造轮子。方案 2 可作为二期可选升级，不影响现在的架构。

## 四、推荐方案的架构

```
客户浏览器
  │ ① 登录（管理员分享码）
  ▼
nginx（443 HTTPS）
  ├─ /web/          静态快照，auth_request 门禁（现有）
  ├─ /ops/progress  只读进度 API（新增，仅管理员可见）
  └─ /ops/scale     触发按钮（新增，POST + 二次确认）
  │ ② auth_request 校验管理员 Cookie
  ▼
门禁服务 gate_service.py（127.0.0.1:8765）
  │ ③ 校验权限、发 CSRF token、写审计日志、加全局锁
  ▼
任务状态文件 run_state.json
  │ ④ systemd service 异步执行
  ▼
run_rerun_5000.sh
  │ 复用：断点续跑 / 双 key 轮换 / $11 成本闸门 / 每日自动续跑
  ▼
新快照生成 → 校验 → 原子切换 → 客户看到 5,000 人数据
```

**设计原则**：按钮只负责"触发 + 显示进度"，跑批逻辑一行都不改，继续复用已经验证过的脚本。这样本地测过的 82 项单测、9 项门禁回归结果继续有效。

## 五、三组需要客户拍板的问题

这三组不定，开发出来也不好用。建议沟通时逐项确认并把答案记进合同/需求确认单。

### A. 权限：谁可以点？

| 选项 | 说明 | 建议 |
|---|---|---|
| A1 独立管理员码 | 复用现有登录页，输入管理员码的人才看到按钮；普通客户码只能浏览 | **推荐**：客户团队几个人，一个管理员码够用 |
| A2 指定 IP 白名单 | 只有办公室出口 IP 能点 | 适合客户有固定公网 IP |
| A3 我们代点 | 不开放按钮，客户提工单我们执行 | 最省事，但不满足"客户点按钮" |

> 不建议"所有持分享码的人都能点"——误点一次就是 $9.8。

### B. 费用：谁承担 $9.8？

需要明确：客户预付 / 项目方包干 / 按实结算后补款。

按钮上建议显示二次确认文案：
> "本次扩容将消耗约 $9.8 OpenAlex 额度，预计 5 天完成。确认开始？"

### C. 体验：等待期间怎么展示？

| 选项 | 说明 |
|---|---|
| C1 进度页（推荐） | 显示"已完成 X/5,000 人、已花 $X/$9.8、当前状态、下次额度重置时间" |
| C2 只显示状态 | 只显示"扩容中/已完成"，信息少但开发量更小 |
| C3 完成通知 | 跑完后发邮件或企微消息，客户不用盯页面（可与 C1 叠加） |

**另外确认两点**：
- 客户能否接受 5 天等待？若不能，需客户提供付费 key（这是唯一提速方式）。
- 跑批期间继续展示 1,000 人旧数据，是否可接受？（建议可接受，无需额外开发。）

## 六、实施拆解（按依赖顺序）

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 1. 权限模型 | 门禁增加管理员码；登录时区分浏览码/管理员码；Cookie 带管理员标志（HMAC 签发，不放明文） | 客户拍板 A |
| 2. 触发端 | `/ops/scale` POST 接口；CSRF token；全局锁防重复点；写审计日志（时间、码摘要、IP） | 阶段 1 |
| 3. 调度器 | systemd service + 每日 timer；额度耗尽自动暂停、次日重置后续跑；状态写入 `run_state.json` | 现有 `run_rerun_5000.sh` |
| 4. 进度 API | 只读 `checkpoint.json`（完成人数）、`cost_ledger.json`（已花费）、`run_state.json`（状态/重置时间）；不回显任何 key | 阶段 3 |
| 5. 前端按钮 | 在二期 DEMO「导出与下一步」页签加入按钮 + 二次确认弹窗 + 进度条 | 阶段 2、4 |
| 6. 快照切换 | 新快照生成到独立目录 → 校验行数与文件完整性 → 原子切符号链接 → 保留旧版可回退 | 阶段 3 |
| 7. 验收 | 未登录不可点、普通码不可点、重复点被拒、进度准确、5 天断点续跑、切换后可下载新工作簿 | 全部 |

**不在本期范围**：多人协同审批、按 scholar 粒度部分扩容、10 万人档（客户另购服务器）、跨库文献检索。

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| 客户误以为点完立刻生效 | 按钮二次确认明示 $9.8 + 5 天；进度页实时显示状态 |
| 重复点击造成重复扣费 | 服务端全局锁 + 状态机，第二次点击直接返回"任务已在进行" |
| 额度耗尽后任务卡死 | 已有断点续跑 + 自动暂停退出码；timer 每日检查重置时间后自动续跑 |
| 成本超出预算 | `$11` 硬闸门在请求发出前拦截，超限时停止并需人工确认 |
| 跑批中途页面数据不一致 | 对外快照不随跑批更新，完成后原子切换 |
| 新数据有问题需要回退 | 旧快照保留，切换脚本支持一键回退 |
| API key 泄漏 | key 只存 `/etc/openalex/api.env`，前端与进度 API 均不回显；建议客户接受后轮换一次 |

## 八、验收标准（建议写进需求确认单）

1. 未登录访问 `/ops/*` 返回 401/302；普通分享码登录后看不到按钮、直接访问返回 403。
2. 管理员码登录后可见按钮；点击弹出二次确认，确认后返回"任务已启动"。
3. 连续点击 3 次，后台只有一个任务实例，成本账本不重复计费。
4. 进度页显示完成人数、已花费、状态、下次重置时间，且与实际文件一致。
5. 额度耗尽自动进入"等待重置"，次日恢复后自动继续，全程无需人工点击。
6. 总额达到 `$11` 前停止，不会突破闸门。
7. 跑批期间 1,000 人快照正常浏览与下载；完成后切换到 5,000 人快照，工作簿可下载且行数正确。
8. 回退操作可将对外数据恢复到切换前版本。
