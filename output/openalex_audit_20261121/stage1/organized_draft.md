# OpenAlex 科学家空间流动数据库项目 验收质疑清单

> 依据文件：`（需求清单）.doc`、`科学家空间流动数据库建立操作1030.docx`、`Table-S1-career-2017.xlsx`、`1030版_新三学者基线与增量对照数据.xlsx`、三份"1030版"PDF 报告（测试报告、满足度说明、逐人轨迹核查报告）。所有数字均可在上述源文件对应 sheet 或页面追溯。本清单用于第一期付款前的验收问询，不构成对数据真伪的司法鉴定。

## 一、项目与本次交付概览

本项目为分四期付款的委托开发，甲方需求清单列出六大模块：数据获取清洗校正、实验数据分析（含空间可视化与双重差分）、文献、论文写作、本地化部署交付，工期均由"双方确认"填写。第一期验收样例明确要求：获取约 20 万高引学者的空间迁移轨迹，通过多源数据库校正，并筛出"中国出生、现阶段在美国居留"的学者群体。

技术方案（2026-10-31 修订稿）将研究对象锁定为 Elsevier 2017 全球高被引名单 105,027 人，数据源从 Scopus 调整为以 OpenAlex 为核心，辅以 ROR、ORCID、Crossref/DataCite，Scopus 仅作非依赖性参考。技术链路分 WP0–WP6 七个工作包，以 C1–C5 事件引擎识别迁移与兼职，最终归入 M1–M8 八类学者。

本次提交的实际材料，是一套围绕三名学者（Becke、Perdew、Newman）的全链路小样本验证数据，以及三份标注"结果与证据边界"的说明报告。

## 二、核心结论

交付物与小样本验证相符，与全量交付相差甚远。对照数据文件的"说明与方法归属"sheet 自载：两人分类不确定、ROR 与原文机构恢复不完整、未做用户审计。三份 PDF 报告标题均含"结果与证据边界"，并明确"只完成小样本，不可宣称全方案通过"。据此，本清单的判断是：可将本批材料认定为第一期的方法可行性验证，但不足以支撑"20 万学者迁移轨迹数据库"的验收，也不足以触发后续各期付款。

## 三、方法内核与判定逻辑

理解质疑点的前提是理解方案设定的判定链条。方案在 WP4 将每位科学家每年的论文署名按机构与分别按国家聚合，出现频次最高者为主机构与主国家，其余为次级；主机构与主国家独立计算，并列时保留并列状态、不强选唯一，无论文年份保留空缺、不以填充值生成事件。

WP5 以相邻两个有效观测年份的主次状态变化识别五类候选事件：C1 为主机构标准 ID 变化而主国家不变（国内迁移候选）；C2 为主国家变化（国际迁移候选，与机构同时变化时优先记 C2、不重复计数）；C3 为新增此前未出现的次级国家；C4 为原主国家降级为次级并在后续年份持续存在，分 pending、confirmed、not_sustained 三态；C5 为机构名称变化但标准 ID 一致，不计入迁移。方案禁止使用 LOCF 填充年作为事件或持续性证据，并规定无论文年份可识别状态变化但须记录观测间隔。

候选事件中的 C1、C2 还须通过自动验证与履历验证：自动验证要求新主机构或主国家连续两个日历年保持主导、署名占比均不低于 60%、累计至少 3 篇不同有效论文；不足者降为 Possible。外部履历（官方个人主页、ORCID 任职记录）确认主要任职机构发生转换者为 Confirmed，论文识别年与履历年相差不超过 2 年的以履历年为准，明确属访问或兼职者为 Rejected。最终以国内迁移 D、国际迁移 I、跨国次级隶属 S 三个二元指标组合为 M1 至 M8 八类学者。

上述逻辑本身完整，但其有效性依赖三个前提：机构与国家识别准确、观测年份连续、外部履历可获取。本批材料在这三个前提上均暴露缺口，构成本清单质疑的主要方向。

## 四、验收质疑清单

### （一）交付范围：验证样本与合同标的严重不匹配

1. 合同第一期样例标的约 20 万学者，方案锁定 105,027 人，实际验证仅 3 人。3 人占 105,027 人的比例约 0.003%。请乙方说明全量数据库的产出时间表、算力与 API 预算，以及 3 人样本如何外推到十万量级。
2. 对照数据共 25 个 sheet，其中轨迹与署名数据全部只覆盖三人。请明确：这是否即为第一期全部交付物？若是，则与第一期标的存在实质性缺口。
3. 需求清单中的空间可视化地图、双重差分（DID）检验、文献模块、论文写作模块、本地化部署，在本批文件中均无对应交付内容。请逐项说明完成状态与计划交付期次。

### （二）数据完整性：机构恢复与署名补全存在系统性缺口

4. "A补查Crossref"共 156 条记录，其中大量条目的 `recovery_status` 为 `matched_author_no_affiliation`、`target_author_not_matched` 或 `http_error`（含 429 限流、301 跳转）。请说明这些记录的最终处置，以及是否影响年度主机构的判定。
5. "A可能机构名称变化观察"达 112 条，方案规定此类 C5 事件须经 WP3 机构标准化核查、确认 ID 一致后方可判定为改名而非迁移。请说明这 112 条的核查完成比例，以及被排除迁移计数的依据。
6. 方案明确预印本跨版本未证实为同一作品时不自动合并，实施口径 sheet 自述"风险另报"。请提供该风险报告，并说明其对论文计数与年度频次的影响。
7. "说明与方法归属"自载"ROR/原文恢复不完整"。请量化机构恢复的完整率，并说明在机构缺失年份是否使用了推断填充（方案禁止用 LOCF 填充年作事件证据）。

### （三）方法口径：关键参数为实施方自行设定

8. "A实施口径"明确记载：机构占比、国家占比的分母定义，以及并列主状态处理口径，是"透明实施解释，非用户原文已明确的参数"，并另列敏感性实验。请甲方确认是否接受这些口径；若不接受，须在确认后重算。
9. 并列主机构/主国家：方案要求"保留并列状态、不强选唯一"，实施口径 S 规则要求"唯一主国家且存在他国有效机构署名才给确证 1"。Perdew 有 3 个并列年、6 条"不确定转换"记录（1974–75、1975–76、1977–78、1978–79、2012–13、2013–14 均因并列不强定方向）。请说明这些年份对 D/I/S 判定的实际影响。
10. 阈值敏感性：对照数据 B 组以 50% 与 70% 独立重算、不覆盖 A 组。70% 阈值下 Becke 的国内迁移次数由 2 降为 1、Possible 事件由 1 升至 2。请说明最终采用哪套阈值作为验收口径，及其对八分类结果的影响。

### （四）分类结论：两名样本无法定类

11. 三名样本中，Becke 与 Perdew 的正式 `mobility_class` 字段为空、`classification_status` 为"分类不确定"，仅"观测组合类"记为 M6；仅 Newman 可分类为 M8（跨国迁移型）。请说明对分类不确定样本的最终处置：是补充证据定类，还是单列为不确定类别。
12. 缺失与并列导致阴性指标不可判定。方案规定"不得将未识别等同于确定无流动"。Becke 有 7 个未观测年、Perdew 有 3 个。请说明在这些缺口下，如何避免把"未发现迁移"误判为"无迁移"。
13. 需求清单要求筛"中国出生、现居美国"学者。本批数据中三名样本均为欧美学者，无任何中国出生样例。请提供该筛选算法的验证样例与准确率证据。

### （五）证据可追溯性：部分字段依赖替代证据

14. "A最终有效迁移时间表"共 6 条迁移。其中 Becke 的 2 条 C1 事件 `actual_migration_year` 为空、`time_basis` 为 `signature_proxy`（以署名年代理真实任职年）；其余 4 条（Perdew 1 条、Newman 3 条）有外部履历年份。请说明 signature_proxy 事件是否可计入"已验证迁移次数"。
15. "B时间差诊断"4 条记录的论文署名年与真实任职年差值均为 +1 年，来源为大学获奖页面与个人主页，且标注"复用 A 证据"。请说明外部证据的采集范围与可核查链接是否完整留存。
16. "A基线请求清单"共 64 条 API 请求，含 sha256 与时间戳（2026-11-01），后端路径显示为服务端临时目录。请说明这批原始响应是否随交付物一并归档，以保证结果可复现。

### （六）测试与审计：规则测试通过不等于业务验证通过

17. 对照数据"规则测试"sheet 列出 19 项单元测试（含 C1、C2 抑制 C1、C3、C4 多状态、C5 去重、八分类、阈值边界等）状态为 passed。请说明这些测试是引擎单元测试，还是覆盖三人真实数据的端到端业务校验。
18. 三份报告与"说明与方法归属"均明确"未用户审计"。请确认用户人工抽样审计的安排：抽样比例、样本选择方式、审计结论的记录形式。

## 六、建议的验收前置条件

综上，建议在付款前要求乙方完成四项前置工作：其一，补齐或明确全量数据库的交付时间表与资源预算；其二，对 112 条 C5 观察与 156 条 Crossref 补查记录完成核查并出具完整率报告；其三，就分母口径、并列规则、采用阈值取得甲方书面确认，并对 Becke、Perdew 给出定类结论或单列不确定类别；其四，启动用户人工抽样审计并留存记录。上述四项完成前，本批材料宜按"方法可行性验证通过"对待，不宜按"第一期数据交付完成"验收。
