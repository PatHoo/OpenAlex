OpenAlex 科学家空间流动数据库项目

验收质疑清单 · 第一期付款前问询（含 1,000 人试跑落库更新）

依据文件：需求清单、建立操作方案（1030 修订稿）、Table-S1-career-2017、新三学者基线与增量对照数据，以及测试报告、满足度说明、逐人轨迹核查报告三份 PDF。甲方资料数字均可在源文件对应工作表或页面追溯；本清单另含 2026-11-22 本机新增的 1,000 人试跑落库结果，来源为 pipeline/README.md、根 README.md 与工作日志，系本机 PostgreSQL 实查。本清单用于验收问询，不构成对数据真伪的司法鉴定。

一、项目与本次交付概览

本项目为分四期付款的委托开发，甲方需求清单列出六大模块：数据获取清洗校正、实验数据分析（含空间可视化与双重差分）、文献、论文写作、本地化部署交付，工期均由“双方确认”填写。第一期验收样例明确要求：获取约 20 万高引学者的空间迁移轨迹，通过多源数据库校正，并筛出“中国出生、现阶段在美国居留”的学者群体。

技术方案（2026-10-31 修订稿）将研究对象锁定为 Elsevier 2017 全球高被引名单 105,027 人，数据源从 Scopus 调整为以 OpenAlex 为核心，辅以 ROR、ORCID、Crossref/DataCite，Scopus 仅作非依赖性参考。技术链路分 WP0 至 WP6 七个工作包，以 C1 至 C5 事件引擎识别迁移与兼职，最终归入 M1 至 M8 八类学者。

本次提交的实际材料包含两部分：其一，围绕三名学者（Becke、Perdew、Newman）的全链路小样本验证数据，以及三份标注“结果与证据边界”的说明报告（甲方 1030 版资料）；其二，2026-11-22 在本机新增的 1,000 人试跑落库结果——WP0–WP11 全部跑通，抓取 922,627 篇作品、去重入库 865,111 篇 work，落库 896 名学者、846,012 条署名、31,388 家带 ROR 的机构，回填 646,069 条署名的机构 ID，并于 2026-11-22 追加跑通分析层：42,046 个学者年面板、13,355 个 C1–C5 事件、53,425 行判据证据，并按原始方案 8.5 完成 896 人 D/I/S→M1–M8 分类（631 人可正式定类、265 人标不确定），数据库约 2.1 GB。

但须明确：新增的仍是“数据地基 + 事件候选 + 初分类”层——年度面板、C1–C5 事件与该事件之上的 D/I/S→M1–M8 分类已算出；但 13,350 条事件的真实任职年份为空（署名代理年），265 人因阴性维度存在 Possible 未决候选而未能正式定类，且中国学者筛选与 DID 尚未运行。因此不能据此宣称“1,000 人迁移轨迹库”已完成，更不能外推为全量交付。

执行摘要

本次交付较上一版有实质进展：在数据地基层，已从 3 人小样推进到 1,000 人试跑（占 105,027 人的 0.95%），作品、学者、署名与机构均已入库，机构识别覆盖率大幅提升（31,388 家机构全部带 ROR，646,069 条署名回填了机构 ID）。分析层已有部分产出：年度面板、C1–C5 事件引擎与 D/I/S→M1–M8 分类已在 1,000 人上运行（13,355 个事件、896 人分类、四判据证据完整），但中国学者队列与 DID 仍为空白，265 人未能正式定类，且事件年份多为署名代理。对照数据文件的“说明与方法归属”工作表亦自载：两人分类不确定、ROR 与原文机构恢复不完整、未做用户审计；三份 PDF 报告标题均含“结果与证据边界”，并明确“只完成小样本，不可宣称全方案通过”。

据此，本清单的判断是：数据与工程能力已得到更强验证（1,000 人规模可落地），但仍不足以支撑“20 万学者迁移轨迹数据库”的验收——因为事件的真实年份多为空、265 人正式分类未生成，轨迹仍停留在候选层，且规模仅为目标的约 1%。本批材料宜认定为“方法可行性验证 + 数据地基施工”，不宜按“第一期数据交付完成”验收，也不足以触发后续各期付款。

二、方法内核与判定逻辑

理解质疑点的前提是理解方案设定的判定链条。方案在 WP4 将每位科学家每年的论文署名按机构与分别按国家聚合，出现频次最高者为主机构与主国家，其余为次级；主机构与主国家独立计算，并列时保留并列状态、不强选唯一，无论文年份保留空缺、不以填充值生成事件。

WP5 以相邻两个有效观测年份的主次状态变化识别五类候选事件：C1 为主机构标准 ID 变化而主国家不变（国内迁移候选）；C2 为主国家变化（国际迁移候选，与机构同时变化时优先记 C2、不重复计数）；C3 为新增此前未出现的次级国家；C4 为原主国家降级为次级并在后续年份持续存在，分 pending、confirmed、not_sustained 三态；C5 为机构名称变化但标准 ID 一致，不计入迁移。方案禁止使用 LOCF 填充年作为事件或持续性证据，并规定无论文年份可识别状态变化但须记录观测间隔。

候选事件中的 C1、C2 还须通过自动验证与履历验证：自动验证要求新主机构或主国家连续两个日历年保持主导、署名占比均不低于 60%、累计至少 3 篇不同有效论文；不足者降为 Possible。外部履历（官方个人主页、ORCID 任职记录）确认主要任职机构发生转换者为 Confirmed，论文识别年与履历年相差不超过 2 年的以履历年为准，明确属访问或兼职者为 Rejected。最终以国内迁移 D、国际迁移 I、跨国次级隶属 S 三个二元指标组合为 M1 至 M8 八类学者。

上述逻辑本身完整，但其有效性依赖三个前提：机构与国家识别准确、观测年份连续、外部履历可获取。本批材料在这三个前提上均暴露缺口，构成本清单质疑的主要方向；新增 1,000 人数据地基虽改善了机构识别 accuracy，但另两个前提仍待事件引擎运行后检验。

三、验收质疑清单

（一）交付范围：规模仍与合同标的不匹配，分析层仅部分产出

  1. 合同第一期样例标的约 20 万学者，方案锁定 105,027 人。甲方 1030 版资料仅验证 3 人（0.003%）；本次新增数据地基扩至 1,000 人（0.95%），其中 896 人完成身份定案、846,012 条署名入库。请乙方说明：1,000 人如何外推到 10.5 万乃至 20 万，全量产出时间表，以及算力、API 额度与磁盘预算（本机 1,000 人已产生 8.6 GB 中间文件、约 2.1 GB 入库）。
  2. 关键缺口——分析层只有候选事件，没有定类轨迹：1,000 人的年度面板、主机构/主国家与 C1–C5 事件已算出，但 13,355 条事件中 13,350 条以署名年代理真实任职年，M1–M8 分类、中国学者筛选与 DID 仍未计算（class_rule 仅回填 M8 一条，无法覆盖其余组合）。请乙方说明事件定级与定类的口径依据，并提供可核查的正式轨迹结果。
  3. 对照数据共 25 个工作表，其中轨迹与署名数据全部只覆盖三人；新增的 1,000 人虽有面板与事件表，但无正式分类结果与可视化轨迹交付。请明确：第一期交付物究竟以哪一批为准，是否存在“只交数据、不交轨迹”的实质性缺口。
  4. 需求清单中的空间可视化地图、双重差分检验、文献模块、论文写作模块、本地化部署，在本批文件中均无对应交付内容。请逐项说明完成状态与计划交付期次。

（二）数据完整性：机构恢复较上版大幅改善，但仍有缺口

  1. 改善项：本次 1,000 人落库中，institution 31,388 家全部带 ROR，institution_alias 181.6 万条，authorship 846,012 条中有 646,069 条（76.37%）回填了机构 ID，占有署名串记录的 95.85%，孤儿外键为 0。请乙方说明剩余有署名串但未匹配机构的 27,977 条有何处置方案，及其对后续年度主机构判定的影响。
  2. 身份质量：Druker（src 466）一名学者对应 25,313 篇署名，源于 OpenAlex 身份合并（抓取阶段即如此），非落库重复。请说明此类高产/同名合并身份在 1,000 人中的规模，以及如何识别并剔除误合并作品——否则年度频次与主机构众数会被污染。
  3. 甲方 1030 版“补查 Crossref”共 156 条，大量条目恢复状态为“匹配作者但无机构”“目标作者未匹配”或“HTTP 错误”（含 429 限流、301 跳转）。请说明最终处置，以及是否影响年度主机构判定。
  4. “可能机构名称变化观察”达 112 条，方案规定此类 C5 事件须经机构标准化核查、确认 ID 一致后方可判定为改名而非迁移。请说明这 112 条的核查完成比例与排除迁移计数的依据；新增 1,000 人机构表后是否已能自动完成此类核查。
  5. 方案明确预印本跨版本未证实为同一作品时不自动合并，实施口径工作表自述“风险另报”。请提供该风险报告，并说明其对论文计数与年度频次的影响。
  6. “说明与方法归属”自载“ROR/原文恢复不完整”。新增 1,000 人数据后请重新量化机构恢复完整率，并明确机构缺失年份是否使用推断填充（方案禁止用 LOCF 填充年作事件证据）。

（三）方法口径：关键参数为实施方自行设定

  1. 实施口径工作表明确记载：机构占比、国家占比的分母定义，以及并列主状态处理口径，是“透明实施解释，非用户原文已明确的参数”，并另列敏感性实验。请甲方确认是否接受这些口径；若不接受，须在确认后重算。
  2. 并列主机构/主国家：Perdew 有 3 个并列年、6 条“不确定转换”记录（1974–75、1975–76、1977–78、1978–79、2012–13、2013–14 均因并列不强定方向）。请说明这些年份对 D/I/S 判定的实际影响。
  3. 阈值敏感性：B 组以 50% 与 70% 独立重算、不覆盖 A 组。70% 阈值下 Becke 的国内迁移次数由 2 降为 1、Possible 事件由 1 升至 2。请说明最终采用哪套阈值作为验收口径，及其对八分类结果的影响。
  4. 消歧口径：本次 1,000 人按“严格 A 级 + 重复行只建 h17 最高主行 + A/B 都建映射”定案，scholar 仅 896 人（3 种子 + 893 新），HOLD 98 人、B 级 178 人待人工复核，5 组源名单重复行各只建 1 名学者。请甲方确认该消歧口径；并说明 98 名挂起者与 178 名 B 级学者的复核计划，及其对样本代表性与统计口径的影响。

（四）分类结论：新增数据已有初分类，但正式定类与口径一致性待核

  1. 三名样本中，Becke 与 Perdew 的正式流动类型字段为空、分类状态为“分类不确定”，仅“观测组合类”记为 M6；仅 Newman 可分类为 M8（跨国迁移型）。请说明对分类不确定样本的最终处置：是补充证据定类，还是单列为不确定类别。
  2. 缺失与并列导致阴性指标不可判定。Becke 有 7 个未观测年、Perdew 有 3 个。请说明在这些缺口下，如何避免把“未发现迁移”误判为“无迁移”。
  3. 新增 1,000 人已初分类，但正式类仅覆盖 631 人：本次按原始方案 8.5.2 节（Word 科学家空间流动数据库建立操作1030.docx）补全 class_rule 八类映射后，896 人均算出 D/I/S 与观测类（M1 6 / M2 21 / M4 160 / M5 2 / M6 467 / M7 87 / M8 153，M3 为 0）；其中 631 人证据充分可正式定类，265 人因阴性维度存在 Possible 未决候选，formal_class 留空、仅记观测类。请乙方说明这 265 人的定案计划，并澄清一处口径分歧：Perdew 在自动署名口径下 1974 年 US→CA 的 Probable C2 使其 I=1→M8，而甲方 1030 版人工核验将其判为访问、记 I=0→M6——两套口径如何统一。
  4. 需求清单要求筛“中国出生、现居美国”学者。三名样本均为欧美学者，无中国出生样例；新增 1,000 人亦未做该筛选（且 OpenAlex/ORCID 无可靠出生国字段）。请提供筛选算法的数据源、验证样例与准确率证据。

（五）证据可追溯性：部分字段依赖替代证据

  1. 最终有效迁移时间表共 6 条迁移。其中 Becke 的 2 条 C1 事件实际迁移年份为空、时间基准为“署名代理”；其余 4 条（Perdew 1 条、Newman 3 条）有外部履历年份。请说明署名代理事件是否可计入“已验证迁移次数”。
  2. 时间差诊断 4 条记录的论文署名年与真实任职年差值均为 +1 年，来源为大学获奖页面与个人主页，且标注“复用 A 证据”。请说明外部证据的采集范围与可核查链接是否完整留存。
  3. 基线请求清单共 64 条 API 请求，含哈希与时间戳（2026-11-01），后端路径显示为服务端临时目录。请说明这批原始响应是否随交付物一并归档，以保证结果可复现。新增 1,000 人试跑共 10,760 次请求留痕在 requests.jsonl，请说明是否同样纳入归档。

（六）测试与审计：规则测试通过不等于业务验证通过

  1. 规则测试工作表列出 19 项单元测试（含 C1、C2 抑制 C1、C3、C4 多状态、C5 去重、八分类、阈值边界等）状态为通过，并已迁入 rule_test 表。请说明这些测试是引擎单元测试，还是覆盖真实数据的端到端业务校验；1,000 人地基上虽已跑通 wp9/wp10 端到端流程，但回归测试覆盖 13 项（7 项失败安全 + 6 项 8.5 分类口径），但均不涉及数据真实性，事件判定与定类结果尚未做人工抽样复核。
  2. 三份报告与方法归属工作表均明确“未用户审计”。请确认用户人工抽样审计的安排：抽样比例、样本选择方式、审计结论的记录形式；新增 1,000 人后是否纳入抽样范围。

五、建议的验收前置条件

综上，建议在付款前要求乙方完成五项前置工作：

  1. 补齐 1,000 人的正式定类与年份证据：class_rule 八类映射已据方案 8.5.2 原文补全，896 人已有 D/I/S 与观测类，但 265 人因 Possible 未决候选未能正式定类，且 13,350 条 signature_proxy 事件无真实任职年份。请对这 265 人出具定案依据，并为 signature_proxy 事件补充履历年份或明确标注为候选——这是把“事件候选”转化为“轨迹库”的关键一步。
  2. 补齐或明确全量数据库（10.5 万 / 20 万）的交付时间表、算力、API 额度与磁盘资源预算，并说明 1,000 人如何外推。
  3. 对 112 条 C5 观察与 156 条 Crossref 补查记录完成核查并出具完整率报告；说明 27,977 条未匹配机构署名与 Druker 类同名合并身份的处置。
  4. 就分母口径、并列规则、采用阈值与严格 A 级消歧口径取得甲方书面确认；对 Becke、Perdew 给出定类结论或单列不确定类别，并说明 98 名 HOLD 与 178 名 B 级学者的复核计划。
  5. 启动用户人工抽样审计并留存记录，抽样范围覆盖新增 1,000 人。

上述五项完成前，本批材料宜按“方法可行性验证通过 + 数据地基、事件与初分类施工完成”对待，不宜按“第一期数据交付完成”验收。
