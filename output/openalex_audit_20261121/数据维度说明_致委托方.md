# OpenAlex 科研分析平台（原科学家空间流动数据库项目）

## 数据维度说明：自助抓取工具与全链路分析成果的关系

> 致委托方｜2026-11-23｜就"网站抓取数据与 1030 版认可样例的差异"作维度层面的说明，供双方对齐理解，不涉及本期验收口径的变更。

---

### 一、结论先行

委托方反馈：使用在线自助抓取工具导出的数据，与 2026-10-30 确认的《新三学者基线与增量对照数据》在维度上差别较大。

对此我们的说明是：**这两份数据处于同一条工作流水线的上下游，是"原料"与"成品"的关系，并非同一份数据的两个版本，也不存在口径矛盾。**

- 在线抓取工具产出的是**原始作品层数据**（论文、作者、机构、引用等 OpenAlex 原始字段），是整条分析链路的**输入**；
- 1030 版认可样例是全链路分析完成后的**成果层数据**（身份消歧、迁移事件、学者分类、轨迹、证据链等），是**输出**。

一个直观的类比：抓取工具交付的是"从数据库检索出的原始论文清单"，而 1030 版样例交付的是"基于这些论文、经过统计与判定后得出的学者迁移结论"。前者是后者的计算素材。

### 二、1030 版认可样例包含的维度（分析层成果）

该样例共 26 个工作表（含说明与原始名单等辅助表），按分析维度可归为七类，均已在 1030 版资料中经委托方确认：

| 维度层 | 具体内容 |
|---|---|
| 身份映射层 | 学者编号、ORCID、消歧等级、抓取篇数、覆盖年份区间 |
| 学者分类层 | D/I/S 三指标 → M1–M8 八类学者；区分观测类别与正式类别、标注不确定项 |
| 迁移事件层 | C1–C5 事件、署名观测年与实际任职年的对照、多项判据证据 |
| 逐人轨迹层 | 主国家/主机构的逐年序列、城市与经纬度、关键事件标注 |
| 证据核查层 | 外部履历证据、时间差诊断、机构名称变化、次级联系终止、DOI 去重 |
| 规则与口径层 | 阈值口径说明、A/B 双轨敏感性设置、19 项规则测试 |
| 请求留痕层 | 逐条 API 请求记录（基线 64 条 + 补查 156 条），可追溯 |

### 三、在线抓取工具导出的维度（原始层）

工具当前提供两种导出，均属原始作品层：

- **作品明细表（CSV，Excel 可直接打开）**：13 列——序号、名单序号、名单姓名、匹配学者、OpenAlex 作者 ID、作品标题、DOI、发表年份、类型、被引数、期刊来源、机构、作者。
- **作品明细（JSONL）**：保留 OpenAlex 返回的完整原始字段，供程序化处理。

这两类导出都不包含上表第二、三、四、五层的分析结论——因为**抓取工具本身不承担分析判定职能**，它只负责把数据从 OpenAlex 取回并整理成表。

### 四、为什么定位不同

| — | 在线自助抓取工具 | 1030 版分析成果 |
|---|---|---|
| 定位 | 数据获取环节的工具 | 分析判定环节的成果 |
| 使用者 | 委托方自行操作，按需抓取 | 我方全链路执行后交付 |
| 产出 | 原始作品记录（原料） | 分类、事件、轨迹、证据（成品） |
| 用途 | 扩充样本、核对原始文献 | 支撑研究结论与验收 |

两者不是替代关系：抓取工具让委托方能够自主、低成本地扩充原始数据；而将这些原始数据加工成 1030 版那样的分析成果，需要运行完整的分析工作包（事件引擎、消歧判定、履历核查等），这部分能力规划在平台后续阶段中交付。

### 五、后续衔接

我方理解，委托方以 1030 版样例作为"认可的数据形态"。后续阶段将把该样例中的分析维度逐步落到平台上，使委托方能够：

2. 将自助抓取工具取得的新数据，接入同一套分析流程，产出与 1030 版同维度的成果；
3. 按委托方确认的口径，导出统一的成果表。
